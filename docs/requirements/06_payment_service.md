# 決済サービス要件定義

## サービス概要

決済サービスは、クレジットカード決済、代引き決済、返金処理などを担当します。

**主な責務**:
- クレジットカード決済（Stripe連携）
- 代引き決済
- 決済状態管理
- 返金処理
- 決済履歴管理

## 機能要件

### 1. クレジットカード決済

#### 1.1 決済処理
- Stripe Payment Intent APIを使用
- 決済フロー:
  1. Payment Intent作成
  2. カード情報確認（3Dセキュア対応）
  3. 決済実行
  4. 決済結果通知
- 決済金額の検証（注文金額と一致）
- 決済タイムアウト: 30秒

#### 1.2 3Dセキュア対応
- SCA（Strong Customer Authentication）対応
- 3Dセキュア認証が必要な場合:
  - 認証URLをフロントエンドに返す
  - 認証完了後に決済実行
- 認証タイムアウト: 5分

#### 1.3 決済失敗
- エラーハンドリング:
  - カード残高不足
  - カード有効期限切れ
  - カード番号不正
  - 3Dセキュア認証失敗
  - Stripe APIエラー
- 失敗理由を記録
- リトライ可能/不可能を判定

---

### 2. 代引き決済

#### 2.1 代引き処理
- 代引き手数料の計算:
  - 1万円未満: 330円
  - 1万円以上3万円未満: 440円
  - 3万円以上10万円未満: 660円
  - 10万円以上: 1,100円
- 決済状態を「代引き受付」に設定
- 配送完了時に決済完了に更新

#### 2.2 代引き決済完了
- Shipping Serviceから配送完了イベントを受信
- 決済状態を「決済完了」に更新
- ショップへ入金予定日を通知（配送完了から7営業日後）

---

### 3. 決済状態管理

#### 3.1 決済ステータス
- **未決済** (`pending`): 決済処理開始前
- **決済処理中** (`processing`): 決済処理実行中
- **3Dセキュア認証中** (`requires_authentication`): 3Dセキュア認証待ち
- **決済完了** (`succeeded`): 決済成功
- **決済失敗** (`failed`): 決済失敗
- **返金処理中** (`refunding`): 返金処理中
- **返金完了** (`refunded`): 返金完了

#### 3.2 ステータス遷移
```
未決済 → 決済処理中 → 決済完了
      ↓             ↓
   決済失敗     3Dセキュア認証中 → 決済完了
                               ↓
                           決済失敗

決済完了 → 返金処理中 → 返金完了
```

#### 3.3 ステータス更新
- Webhook経由でStripeからステータス更新を受信
- ステータス更新時にイベント発行

---

### 4. 返金処理

#### 4.1 全額返金
- 注文キャンセル時に全額返金
- Stripe Refund APIを使用
- 返金処理時間: 5-10営業日（クレジットカード会社による）

#### 4.2 部分返金
- 一部商品のキャンセル時に部分返金
- 返金金額の検証（決済金額を超えない）

#### 4.3 返金履歴
- 返金日時
- 返金金額
- 返金理由
- 返金ステータス
- Stripe返金ID

---

### 5. 決済履歴管理

#### 5.1 決済履歴照会
- ショップ運営者: 自分のショップの決済履歴
- カスタマー: 自分の決済履歴
- 管理者: すべての決済履歴
- フィルター:
  - 期間
  - 決済ステータス
  - 決済方法
- ソート: 決済日時

#### 5.2 決済詳細
- 決済ID
- 注文ID
- 決済方法
- 決済金額
- 決済ステータス
- 決済日時
- Stripe Payment Intent ID
- 返金情報

---

### 6. Stripe Webhook

#### 6.1 Webhook受信
- Stripeからのイベント受信:
  - `payment_intent.succeeded`: 決済成功
  - `payment_intent.payment_failed`: 決済失敗
  - `payment_intent.requires_action`: 3Dセキュア認証必要
  - `charge.refunded`: 返金完了
- 署名検証（Stripe Webhook Secret）
- 冪等性保証（イベントID記録）

#### 6.2 Webhook処理
- イベント種別に応じた処理:
  - 決済ステータス更新
  - Order Serviceへイベント発行
  - Notification Serviceへ通知依頼
